# M7 — yt-dlp Video Source Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** YouTube videos resolve reliably again. On 2026-11-02, device testing found that YouTube answered every `youtube_explode_dart` stream URL with HTTP 403, and the library re-fetched manifests in a loop (65 MB used, no audio). yt-dlp, bundled through `youtubedl-android` and updated inside the app, replaces it.

**Architecture:**
- yt-dlp only **resolves** a video: `yt-dlp -J` returns title, channel, length, every format's URL and size, and the caption tracks as JSON. It runs in Kotlin through `youtubedl-android` behind the `status_studio/ytdlp` channel.
- The app still **downloads** in Dart (`HttpClient` range requests): whole files in 10 MB ranges through `RangedDownloader`, clips through the existing `sidx` path (FR-15). Measured on 2026-11-02: yt-dlp URLs download at about 10 MB/s with plain range requests and no extra headers.
- `youtubedl-android` bundles Python, yt-dlp and QuickJS, and passes `--js-runtimes quickjs:<path>` itself, so YouTube's JS challenges are solved on the phone.
- `YouTubeVideoSource` stays the only class that talks to YouTube; `youtube_explode_dart` is removed.

**Tech Stack:** `io.github.junkfood02.youtubedl-android:library` 0.18.1 (Gradle), `dart:io` `HttpClient`.

**Spec:** FR-1, FR-2, FR-3, FR-15, §5 Package map, §8, §9 Distribution, §10 Q4.

## Global Constraints

- M1–M6 Global Constraints apply.
- Android only. iOS isn't built yet; it would need another resolver behind `VideoSource`.
- No yt-dlp call in tests: Dart tests fake `YtDlp`; downloads in tests hit a loopback `HttpServer` only.
- yt-dlp updates itself at most once a week (about 3 MB), and once more when it fails to read a video.
- Auto-generated caption tracks: only yt-dlp's `<lang>-orig` track is the one YouTube heard; the others are machine translations of it and are never used.
- HLS formats (`protocol` not `https`, no `filesize`) are skipped: they can't be fetched in byte ranges.

## Review Focus

- **A video yt-dlp can't read** must end in a §8 message after one update-and-retry, not a loop. Test: Task 5 `extraction_failure_updates_once_then_reports`.
- **Translated auto-captions** must never become a script. Test: Task 3 `auto_captions_use_only_the_orig_track`.
- **Live streams and videos without a length** are unavailable. Test: Task 3 `live_stream_is_unavailable`.
- **Whole-file downloads** go through `.part` + rename, in ranges. Test: Task 4 `script_audio_downloads_lowest_bitrate_in_ranges`.

**Interfaces:**
- Channel `status_studio/ytdlp`:
  - `quickVideoInfo(videoId)` → the `-J` JSON without a JavaScript runtime (`--no-js-runtimes`): only YouTube clients that need no challenge solving.
  - `videoInfo(videoId)` → the same with QuickJS solving YouTube's challenges; slower, for videos the quick run can't read.
  - Error code `ytdlp_failed` with yt-dlp's stderr as the message.
  - `update()` → `"updated"` or `"up_to_date"`.
  - `version()` → `yt-dlp --version` (the library only knows the version after an update).
- yt-dlp runs on a single background thread; `YoutubeDL.init` runs once, lazily, on that thread.
- `fun videoInfoOptions(cacheDir: String)` → `-J --no-playlist --no-warnings --cache-dir <dir> --extractor-args youtube:skip=hls,dash`; `quickVideoInfoOptions` adds `--no-js-runtimes`. They go in as commands, after the library's own `--js-runtimes quickjs:…`, so the quick run's flag wins.
- Gradle: `packaging { jniLibs { useLegacyPackaging = true } }`, so the bundled Python is extracted on install; `keepDebugSymbols` for `libpython.zip.so`, which isn't an ELF file.
- Spec: plan said to measure a release build; the phone had a debug-signed install holding the speech model, so the timing used a profile build. yt-dlp runs in its own Python process, so Flutter's build mode doesn't change it.

**Interfaces:**
- `class WorkAmount { int done; int total; WorkUnit unit; double get fraction; }`, `enum WorkUnit { bytes, audioMilliseconds }`.
- `class WorkRate { WorkRate.from(WorkAmount first, Duration at); double? perSecond(WorkAmount latest, Duration at); }`: the step's average since this run first saw it.

- `ScriptProgress.step`: the current stage's amount. Model and audio downloads report bytes; transcribing reports audio done (whole 90 s chunks) of the video's length. Detecting the language has no amount: Whisper detects it inside the first chunk.
- `ModelManager.download` emits `WorkAmount`s; `VideoSource.downloadScriptAudio` reports `WorkAmount`s.
- Processing shows each measured step's line under its detail and keeps it once the step is done.
